Developer storage

Clear Xcode Derived Data safely

Derived Data is generated build output. It can grow large, and Xcode can regenerate it—but that does not mean every developer folder should be deleted without review.

What Derived Data contains

Xcode uses Derived Data for build products, indexes, intermediates, module caches, and related generated files. Removing eligible generated output normally means the next build takes longer while Xcode recreates what it needs.

What to do before cleanup

  • Stop an active build, test run, archive, simulator task, or Xcode update.
  • Save work and make sure you are looking at generated storage rather than your project source.
  • Review each path: separate child entries may be shown so their size and purpose are understandable.

Use a reviewed cleanup path

Second Wind recognises specific rule-approved Xcode-generated locations. It explains the matched rule and supported destination, then requires your selection and final confirmation. It does not scan arbitrary project folders or decide that source code is disposable.

For additional caution, choose local Recovery rather than Finder Trash. Recovery keeps a local manifest and payload so you can restore the item later. Finder Trash remains useful when you prefer macOS’s usual deletion route.

What not to remove as “Xcode data”

Do not treat all developer storage as Derived Data. Repositories, archives you intend to keep, signing material, simulator content you rely on, project configuration, and unknown support paths need their own explanation and policy.

Common questions

Will clearing Derived Data break a project?

Eligible Derived Data is generated output rather than project source, and Xcode normally recreates it. A later build or index may take longer. That distinction depends on the exact path, which is why Second Wind uses specific approved locations instead of treating every directory under Developer as disposable.

Should Xcode be running during cleanup?

Finish active builds, tests, archives, simulator work, and updates first. Files can change while Xcode is working, and a source that changes after review should not be assumed to match the plan. Re-scan when the developer tools are idle if the displayed state is no longer current.

Expected result

You may reclaim storage, but Xcode may rebuild caches later. That is normal; the point is to remove reviewed generated output, not to permanently optimise a Mac.
