Storage basics

Find what is using storage on your Mac

Start by building a picture of storage. Do not begin by deleting folders whose names merely sound temporary.

Start with the largest known areas

macOS can show available storage and broad categories, but a category is not automatically a cleanup instruction. Look for a concrete path, a size, an owner, and a reason before treating an item as a candidate.

Second Wind scans the locations it explicitly understands and presents the resulting local inventory by category. A completed scan is read-only: it observes storage without moving anything.

Separate known storage from unknown storage

  • Known: an observed path has a category, origin, protection state, and supported action.
  • Protected: the location may be shown so you can understand it, but it cannot join a cleanup plan.
  • Unknown: absence from a storage tool is not proof that it is safe to remove.

Use a deliberate sequence

  1. Run a read-only scan.
  2. Sort the known entries by size or category.
  3. Open the explanation for an item you are considering.
  4. Select only the entries you recognise and want reviewed.
  5. Read the complete cleanup plan before confirming a destination.

When the number does not match free space

Planned bytes and observed free-space changes can differ. APFS allocation, snapshots, purgeable storage, and files that are still in Finder Trash all affect what macOS reports. Treat the inventory as an explanation of known paths, not as a promise that every byte will instantly become free.

Common questions

What should I inspect first?

Start with the largest category that Second Wind can explain, then open its individual entries. Developer storage, large application bundles, Downloads, and Recovery often provide clearer evidence than a broad system category. Size helps you prioritise inspection; it does not establish that an item is safe to remove.

Why did a category change between scans?

Applications continuously create and remove caches, build output, logs, downloads, and support files. Second Wind compares completed inventory snapshots, so the change describes known storage observed at two points in time. It does not diff file contents or claim that every change was caused by Second Wind.

Keep the boundary

A large folder is not enough evidence to delete it. If Second Wind cannot explain the path and its supported action, leave it protected.
